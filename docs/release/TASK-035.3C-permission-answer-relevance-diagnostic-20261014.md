## Score semantics and correction decision

Vector `relevance_score` is `1 - cosine_distance` on a 0–1 scale and is filtered by the configured minimum before hybrid fusion. Keyword rank is PostgreSQL `ts_rank_cd`, non-negative and not comparable with cosine relevance. Hybrid score is reciprocal-rank fusion, not a probability. Cross-encoder model scores are normalized to 0–100 *within the current candidate set* (single or tied sets become 50), then added to non-negative heuristic alignment. Heuristic zero is a floor and the `HybridRetrievalHit.reranker_score` may also be `None` for unreranked/adjacent candidates. Query decomposition can merge hit groups with different scoring contexts. Therefore “reranker score == 0” or one global score threshold is not a defensible generic NO_ANSWER gate.

The validator defect is **verified**, but the complete causal chain is only **partially verified**: raw generation/retry output and raw per-channel/model relevance scores were not preserved; the candidate DB is now unavailable without restarting its exited service. A lexical overlap gate would reject legitimate English-question/Vietnamese-evidence answers, and an uncalibrated cross-encoder cutoff would have the same regression risk. No sufficiently evidenced *safe correction* was established under the bounded scope. In accordance with the stop rule, no production change, threshold, retry increase, prompt change, benchmark-specific rule, or candidate rebuild was made.
