# TASK-035.3M — minimal CI security-gate implementation proposal

Date: 2026-10-14. **Design only; `.github/workflows/ci.yml` was not edited or run.** Current workflow has one backend job on push/PR, Python 3.12, `contents: read`; full-tree Ruff, broad tests, a narrow custom security script, migration checks and Docker build are configured. No frontend job, current advisory job, comprehensive secret scan or required-status evidence exists. Keep red RAG contracts visible. Proposed commands below are for a future **isolated Linux runner**, not this host/V2 runtime; tool/action versions, script policy and data-transmission permission require owner review before YAML changes. Preserve `contents: read` and no production secrets for PR jobs.

All proposed jobs trigger on the existing push/PR events; required merge/release status needs explicit branch-protection/release-owner approval (not visible locally). No third-party action or binary is approved. Scanner setup and browser download add network/time/cost and require budget/reproducibility review. Current backend CI's broad online dependency resolution and model downloads remain a separate provenance limitation. Final-image scanning/SBOM and deployment approvals remain necessary later release gates even though this table focuses on minimal dependency/frontend security CI. A current workflow run cannot be inferred from YAML, and no changes should be made merely to turn red tests green.
