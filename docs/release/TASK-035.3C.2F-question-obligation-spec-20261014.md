# TASK-035.3C.2F — question–answer obligation evaluation specification

Date: 2026-10-14. Scope: bounded offline synthetic research only. This is a proposed research subphase, not a pre-existing release contract. No production correction, candidate build, service change, corpus use, or new dependency/model download is authorized or performed.

## Evidence and causal boundary

The authoritative [035.3C diagnostic](TASK-035.3C-permission-answer-relevance-diagnostic-20261014.md) verifies a STAFF answer that cited an authorized but unrelated post-incident-rest clause when asked about a private travel-approval fact. It verifies an unsafe final-acceptance boundary: a verbatim clause can be `SUPPORTED` by `ClaimEvidenceValidationService` without answering the question. It also identifies context admission of irrelevant visible evidence as the first *observed* unsafe progression. Raw channel/model scores and the exact generation/retry draft were not preserved, so the first generation origin and full causal chain remain unproven. The private source did not leak in the recorded response. A–O is a synthetic proposed contract, not a passing test suite: the prior checkpoint observed 8/15 failures (five unsafe accepts, three false abstentions).

The prior [2E evaluation](TASK-035.3C.2E-decision-20261014.md) tested the current validator, a cached multilingual E5 whole-answer similarity score, and local Qwen whole-answer rubrics on 12 development/24 now-exposed pilot cases. None met both safety and valid-answer usefulness. The revised Qwen rubric recovered development positives but accepted omitted conditions, reversed prohibition, and unresolved authority conflict. No blind claim applies to that revision. A relative reranker zero or simple lexical overlap has no proven relevance/entailment semantics. `analyze_question` supplies answer shape and selected flags, not an arbitrary bilingual subject–action–object–condition–authority graph. These observations justify, but do not prove, a question-obligation decomposition hypothesis.

## Obligation contract and six separate dimensions

An obligation is an atomic proposition needed to answer the original question completely, not a citation, answer claim, keyword, or policy authority. Depending on the question it may bind an entity and attribute; subject, action and object; actor/approval authority; amount and benefit; event order; mandatory condition/exception; negation; or multiple independent document-backed parts. An answer must preserve material qualifiers, not merely mention the topic. The extraction stage may use the original question and **authorized evidence only**, never the proposed answer or restricted evidence. Human-authored `obligations` in the new manifest are a review/diagnostic reference, not input to the automatic prototype or independent truth about policy.

| Dimension | Meaning | This offline experiment's evidence and limitation |
| --- | --- | --- |
| A. Authorization | Can the requesting user use each evidence item? | The manifest explicitly separates authorized/restricted synthetic fields; only authorized fields enter registry/model. This does **not** retest production RBAC. |
| B. Evidence relevance | Does accessible evidence address the requested relation? | Extraction emits `evidence_relevant`; inspect separately, not as cosine. It can be wrong. |
| C. Claim support | Does cited evidence entail the proposed factual answer? | Existing validator is the baseline; it is already known to over-accept some verbatim unrelated/incorrect claims. |
| D. Answer coverage | Does the answer supply all requested propositions? | Local cached E5 computes cosine for each extracted obligation against the answer; minimum score is a diagnostic, not entailment probability. An oracle run substitutes author-written obligations only to isolate extraction from coverage. |
| E. Conditions/exceptions | Are mandatory scope and timing intact? | They should appear as separate atomic obligations; missing extraction or semantic overmatch invalidates the check. |
| F. Conflict/authority | Are mutually opposed accessible sources unresolved? | Extraction emits `unresolved_conflict`; no document supersession is inferred. A missed conflict is not rescued by a low similarity score. |

`REJECT` means this proposed answer must not be accepted. `UNCERTAIN` is reserved for unresolved source authority or evaluator failure, not an automatic synonym for missing evidence. For release, both are safe non-accepts, but exact three-way labels matter. A grounded unrelated statement can pass C while failing B/D; a responsive unsupported statement can pass D while failing C; omitted conditions can appear topically similar yet fail E.

## Frozen independent set and predeclared methods

The new [synthetic manifest](../../artifacts/task-035-3c2f-20261014/synthetic-manifest.json) was frozen before execution, SHA-256 `e58b81b46df6cc9cc1f18b9a68484957974a951e9c60377946b841d076156a13`: 12 development and 24 untouched-until-one-shot-final-test cases, the latter eight EN/eight VI/eight MIXED and 10 ACCEPT/12 REJECT/2 UNCERTAIN. It uses invented museum, garden, archive, and benefit policies, not 2E cases, benchmark answers, or private V2 documents. Some within-final pairs share synthetic policy wording; the observations are correlated and not a population accuracy estimate. One author supplied gold/rationales; no independent multi-annotator adjudication has occurred.

The [experimental harness](../../scripts/release/task0353c2f_eval.py) compared on the **same cases**: (1) existing `ClaimEvidenceValidationService` with an authorized-only registry; (2) automatic Qwen `qwen2.5:3b` extraction from question+authorized evidence, followed by cached offline E5 minimum per-obligation coverage, relevance/conflict gates; (3) their intersection; and (4) an **oracle-obligation diagnostic**, using reviewed manifest obligations instead of model extraction, which is not deployable. The extractor is a materially different experiment from the failed holistic Qwen judge: it does **not** see or classify the proposed answer, and is intended to expose extraction separately from coverage. Its generated propositions may still hallucinate. No other LLM judge, model or dependency was added.

For both automatic and oracle cosine diagnostics, one threshold was selected solely on the 12 development cases using the declared cost `2 × unsafe_accept + false_abstain`, tie-breaking toward fewer unsafe accepts and a higher threshold. The selected values were automatic `0.898772` and oracle `0.945443`; neither was changed after inspecting final-test outcomes. Evidence absence deterministically rejects; malformed extraction or an extractor-marked conflict gives UNCERTAIN. The intersection accepts only when both existing and automatic methods accept. These are experimental decisions, not proposed release thresholds.

The final-test set was evaluated once after this method was fixed. No later retuning or test-set revision is claimed as blind confirmation. The prior 2E held-out pilot is exposed and is not reused as unseen evidence. See [results/decision](TASK-035.3C.2F-results-decision-20261014.md) and [gold-label review](TASK-035.3C.2F-gold-label-review-20261014.md).
