# TASK-035.3C.2E — isolated evaluation design and execution contract

Date: 2026-10-14. This is an experimental, synthetic-only evaluation of final-answer responsiveness and entailment, **not** a production implementation or release qualification. The frozen TASK-035.3B candidate remains FAILED. TASK-035 remains IN PROGRESS. No existing A–O regression expectation, production source, Docker image, service, PostgreSQL/Redis state, or UAT Corpus v2 source was changed.

## Objective and check separation

The target decision is whether a proposed **final** answer materially responds to the original question using only evidence authorized to the requesting user. That requires distinct checks: (1) authorization of each source before evaluation, (2) evidence relevance to the *question's requested relation*, (3) entailment of each answer claim by its cited evidence, (4) answer responsiveness to the information need, (5) completeness of mandatory conditions/exceptions, and (6) final safety and conflict handling. Citation identity or source-grounded wording alone is not a relevance verdict. A same-topic number or high embedding similarity is not proof of relation binding.

The production call contract was inspected: `GroundedAnswerService._draft_from_generation` receives the resolved question, validates citations, invokes `ClaimEvidenceValidationService.validate`, and returns ANSWERED for `SUPPORTED`. Ordinary retry generations are revalidated; compound claims are checked per information need before an already-validated combined draft. `analyze_question` classifies answer shape (`PERSON`, `YES_NO`, `POLICY_CONDITION`, etc.) and some numeric/time intent but does not extract a general subject-action-object-authority-condition graph. A verbatim source clause can return `SUPPORTED` before generic responsiveness is established. This is the diagnosed first final-acceptance defect, independent of earlier context admission of irrelevant permission-visible sources.

## Frozen synthetic corpus and gold

The [manifest](../../artifacts/task-035-3c2e-20261014/synthetic-manifest.json) was created and SHA-256 frozen (`efa29ae911d3b90d7b48c515f41f687289f85812637627a5f2c4f7be586d3e4f`) before model execution. It contains 36 invented policy cases: 12 development, 24 held-out (8 English, 8 Vietnamese, 8 mixed), with 10/12/2 held-out ACCEPT/REJECT/UNCERTAIN labels. Each case has a question, final answer, authorized evidence, optional restricted *synthetic* evidence, tags, and explicit gold rationale. Labels are reasoned for this evaluation, not independently adjudicated by multiple human reviewers. The original A–O tests are unchanged and were not used as the held-out set.

Coverage includes exact and paraphrased answers, low-overlap English/Vietnamese translation, grounded but nonresponsive text, wrong actor/action, negation, false premise, conditions, numbers tied to the wrong policy, unsupported answers, multi-document support, missing authorized evidence, permission-limited questions, prompt injection embedded in a synthetic source, and unresolved contradictory authority. The harness passes **only** `authorized_evidence` to models. The presence of a synthetic restricted source cannot create support; the proposed answer itself is necessarily visible to a judge and may coincidentally state the restricted fact, a separate privacy consideration for any future external provider.

## Predeclared methods and operational constraints

- **A, existing deterministic/structured validator:** run `ClaimEvidenceValidationService.validate` with a synthetic authorized-only `PromptSourceRegistry`; map `SUPPORTED` to ACCEPT and other statuses to REJECT. This tests current structure and relations, not production RBAC or API persistence.
- **B, existing local semantic encoder:** use only the complete cached `intfloat/multilingual-e5-small` snapshot (revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`, 470,641,600-byte safetensors SHA-256 `1a55775f53449dac10a2bcbc312469fac40b96d53198c407081a831f81c98477`) in CPU/offline mode. Score the minimum of question–answer and authorized-evidence–answer cosine. Select one threshold on development by minimizing `2 × false acceptance + false abstention`, tie-breaking to fewer false accepts and then a higher threshold. Never retune on held-out. Similarity is not an entailment probability.
- **C, constrained local judge:** verify `qwen2.5:3b` is already installed (digest `357c53fb659c5076de1d65ccb0b397446227b71a42be9d1603d46168015c9e4b`) and call only localhost Ollama with synthetic question, final answer and authorized evidence, temperature 0, fixed seed, bounded context/output and 75-second request timeout. Use structured dimensions and map malformed output/timeout to UNCERTAIN. Do not send private UAT text or invoke an external provider. The initial rubric ran the same 24 held-out as A/B as a pilot; development-only revisions and their limitation are recorded in [prompt versions](../../artifacts/task-035-3c2e-20261014/judge-prompt-versions.md).
- **Hybrids:** compare only simple predeclared A AND B, A AND initial C, and A OR B on the same pilot held-out predictions. A cascade is not presumed beneficial. Do not add production dependency/calls.

The local BGE cross-encoder was **not** evaluated: read-only listings of both the host cache and the active V2 API's model-cache mount for configured `BAAI/bge-reranker-v2-m3` found a ref and an empty `.no_exist` marker but no model weights. The protected stopped-candidate volume was not mounted or inspected for this purpose. Downloading or installing BGE was prohibited. The cached E5 encoder was actually loaded with `HF_HUB_OFFLINE`/`TRANSFORMERS_OFFLINE` and a local snapshot path; no model download occurred. The Ollama judge used the already-installed local model and no application API endpoint.

The harness is [task0353c2e_eval.py](../../scripts/release/task0353c2e_eval.py); [harness unit tests](../../tests/unit/test_task0353c2e_eval_harness.py) verify split integrity, restricted-source exclusion, malformed-output abstention, conflict rule, development-only threshold selection, transport payload scoping and timeout abstention (7/7 PASS). It writes only per-case IDs, scores/dimensions, decisions, latency, usage and aggregate metrics—not raw prompts or evidence. The manifest itself is synthetic and contains the gold/rationales. Output hashes and metrics are in [comparative-metrics.md](../../artifacts/task-035-3c2e-20261014/comparative-metrics.md).

## Decision standards and limits

No release acceptance threshold was documented for this experimental evaluator. Proposed engineering criteria for owner review, **not approved release thresholds**, are: zero false acceptance on all identified high-risk development controls (negation, condition omission, permission, unsupported answer, authority conflict); no false abstention on essential multilingual/multi-document positive controls; invalid-output and timeout paths never return ANSWERED; no inaccessible source can enter a judge prompt; bounded p95 and cold-start/resource cost compatible with the actual release SLO; and confirmation on a fresh, independently reviewed held-out corpus without prompt/threshold retuning. A 24-case held-out with two conflict cases cannot establish population safety, even if all pass. A robust candidate would then need targeted RAG/RBAC/citation and broad V2 requalification in a new isolated build under separate authorization.

The initial judge held-out became exposed during prompt-failure analysis; later rubric changes were checked only on development cases. The final schema-constrained rubric failed development safety (three unsafe accepts), so no new confirmatory held-out set was consumed. This preserves the distinction between exploratory pilot and blind confirmation. See the separate [decision record](TASK-035.3C.2E-decision-20261014.md).
