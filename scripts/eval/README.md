# UAT Q001-Q100 eval harness

Used in PROMPT 3d/3e to compare the runtime before and after a change on an isolated stack.
It never touches the V2, AUTH-02 or main stacks.

| File | Purpose |
|---|---|
| `compose.uat-eval.yaml` | Overlay on `compose.yaml` + `compose.uat-corpus-v2.yaml`. Uses its own image (`P3D_BACKEND_IMAGE`), publishes no DB or Redis ports, and puts the API on 127.0.0.1:18190. Always run it with its own `-p` project. |
| `bootstrap_corpus_v2.py` | Uploads UAT Corpus v2 through the API (hash check, READY wait, grants). Writes its runtime manifest to the path you pass, never to the V2 evidence file. |
| `ollama_warmup.py` | One warm-up request with the app's model, `num_ctx` and `keep_alive`, sent before the questions. Its time goes into the run metadata and it is not scored. |
| `run_uat.sh` | One run: metadata, warm-up, the existing runner `tests/acceptance/rag_h5_2_exact_100.py`, then the proxy grade. The runner retries each `INFRA_ERROR` case once at the end of the run (`--resume` does not retry it again); `metadata.json` records `infra_error_cases`, `infra_error_retried_cases` and `infra_error_ids`. |
| `eval_client.py` | HTTP client of the runner: one keep-alive `httpx.Client` per run. Transport errors, timeouts, 5xx, a 2xx without an answer body and a 429 after its retries are `INFRA_ERROR`, never `OK`; other 4xx are `HTTP_ERROR`. |
| `grade_proxy.py` | Proxy grade against the TASK-035.3B agent grade: status plus cited document codes. **Not a semantic grade.** `INFRA_ERROR` cases are excluded from the score; the summary reports `scored_cases`, `excluded_infra_error` and their IDs, and `by_route`: cases and proxy matches per answer route. Since DEC-032 each case also has `values` and `value_match` (`proxy_match` plus the reference's values); the categories, `metrics.py` and `compare_flag_runs.py` use `value_match` when present. |
| `value_grading.py` | DEC-032 value-aware grading: an answer must state every value of its reference (numbers with unit, money, times, dates, normalized as in the claim validator) and no other value in the same unit. Used by `grade_proxy.py` and the dev-set runners (conflict check on top of their fact forms). `value_grading.py regrade <set> <results.json> <out.json>` regrades a stored run without running it again. |
| `compare_before_after.py` | Splits cases into (a) identical in every run and (b) changed; (b) is split again into b1 (baseline already varied) and b2 (new change). |
| `reranker_check.py` | Reads `reranker_mode` from `GET /health/ready` and refuses a run whose mode differs from `--expected-reranker-mode` (or `EVAL_EXPECTED_RERANKER_MODE`), unless `--allow-reranker-fallback` accepts `lexical_fallback`. `run_uat.sh` and `run_heldout.sh` expect `lexical_fallback` on the current stacks and write the mode to the metadata. |
| `ollama_check.py` | Reads the Ollama version (`/api/version`) and backend (the `inference compute` lines of the server log, `EVAL_OLLAMA_LOG` or `%LOCALAPPDATA%\Ollama\server.log`). `reranker_check.guard` calls it, so every runner refuses a run on another version or backend than `EVAL_OLLAMA_EXPECTED_VERSION`/`EVAL_OLLAMA_EXPECTED_BACKEND` (default 0.40.15 and CUDA, DEC-014), records both at the start and the end, and marks a run invalid when they change. |
| `ci_batch.sh` | One measurement batch inside an Actions job (`eval.yml`, DEC-016): it first validates the set, the configurations and the accounts (`batch_sets.py`; `--validate-only` stops there, with no stack, API or model); each flag configuration runs 1 or 2 times on the same image and Ollama, interleaved; the UAT set is proxy-graded, the RBAC set also gets the retrieval leak check; later configurations are compared with the first through `compare_flag_runs.py`. Writes `batch.json` (Ollama version and backend), `summary.md` and `compare-<name>.json`, and saves each API container's log (`<config>/run<n>/api.log`, `before-batch/api.log` for the corpus load; the worker's since the run began in `worker.log`) before the next recreate removes it; the last container stays for the workflow's log step. A configuration with no setting is the default of DEC-040 (simple + s1-s3 + `qwen3.5-text:4b`); the rollback is `legacy:EVAL_ANSWER_MODE=legacy,EVAL_LLM_MODEL=qwen2.5:3b`. `EVAL_SIMPLE_LEVEL=n` turns s1..sn on and the later flags off. |
| `metrics.py` | Per-run `permission_leak_count`, `false_answer_rate`, `false_refusal_rate`, `answer_accuracy`, `citation_accuracy`. Held-out uses the owner's labels and refuses blank ones; dev uses `grade_proxy.py` output, is marked `proxy` and reports the leak count as null (not measured). UAT scores also report `by_route` (correct and wrong ids for `deterministic` and `llm`, and a `route …` row in `score.md`), because the UAT total mostly measures server-built answers. |
| `run_rbac_dev.py` | RBAC dev set from `tests/acceptance/rbac_dev_v1.yaml` on the isolated stack `eaka-rbac-dev`: 18 questions from accounts without access, each with a control from an account with access. Controls run first, then the grant is revoked, then the negatives. Score with `metrics.py rbac`. |

| `run_answer_relevance_dev.py` | Frozen relevance dev set from `tests/acceptance/answer_relevance_dev_v1.yaml` on the isolated stack `eaka-relevance-dev`: questions the documents do not answer, with similar ones they do. Refuses a set that differs from its lock. |
| `branch_counters.py` | Reads `enterprise_ai_rag_answer_branch_total` from `GET /metrics`. The relevance, RBAC and UAT runners record the change over the run as `branch_counters`; `null` means not measured. The UAT runner also reads `route_deterministic` / `route_llm` around each question and stores the case's `answer_route` (`deterministic`, `llm`, or `null` when no counter moved). |
| `compare_flag_runs.py` | Compares two baseline runs with two runs of a flag on the relevance, RBAC or UAT set. A case counts as changed only when both sides agree within themselves and differ from each other. |

Compare a flag only with a baseline from the same batch: same image, same session, Ollama not restarted, runs interleaved (DEC-011).

RBAC dev stack (never add these documents to the main corpus):

```bash
export P3D_BACKEND_IMAGE=eaka-backend:<tag>
docker volume create eaka-rbac-dev_model_cache   # copy the e5 cache in from another stack
docker compose -p eaka-rbac-dev -f compose.yaml -f compose.uat-corpus-v2.yaml \
  -f scripts/eval/compose.uat-eval.yaml up -d --no-build
python scripts/eval/run_rbac_dev.py --output artifacts/rbac-dev/run/runtime_results.json
python scripts/eval/metrics.py rbac artifacts/rbac-dev/run/runtime_results.json
python scripts/diagnostics/rbac_retrieval_check.py --container eaka-rbac-dev-api-1 \
  --output artifacts/rbac-dev/retrieval.json
```

The runner needs `EVAL_PASSWORD_ADMIN`, `_MANAGER`, `_STAFF` and `_OPS` in the environment and `EVAL_EXPECTED_RERANKER_MODE=lexical_fallback` on a stack without cross-encoder weights. Keep the same `_OPS` value between runs: it is set when the account is created.

| `heldout_v2_check.py` | Checks held-out v2 against its frozen questions and the PDF pages, reports overlap numbers and writes the gold review. Never runs the system (DEC-012). |
| `heldout_v3_release.py` | DEC-035/036/038 held-out v3.1 run, prepared but not run: `gate` (the v3.1 lock of DEC-038; PENDING items excluded), `run` (one configuration, called by `ci_batch.sh` set `heldout_v3`, allowed only inside `.github/workflows/heldout-v3.yml`), `grading` (counts, DEC-035 verdict, grading.md / grading.csv). Items whose test account maps to no seeded user are not asked. Prints ids and counts only. |
| `heldout_v2_release.py` | Phase 3 release run of held-out v2, prepared but not run (`docs/design/heldout-v2-release.md`): `gate` (frozen questions plus owner-approved gold lock), `preflight` (gate, reranker, Ollama and logins with the stack up; sends no question), `lock-gold`, `run` (2 runs on Actions through `.github/workflows/heldout-v2.yml`, current defaults), `near-uat` (e5 >= 0.90 to Q001-Q100), `grading` (grading.md / grading.csv, labels empty), `report` (after the owner's labels, split near UAT / rest). Every sheet states DEC-022. |
| `batch_sets.py` | The registry of `ci_batch.sh` sets (uat, rbac, relevance, false_refusal, false_refusal_v2, compound, natural, heldout_v3). `validate <set> --configs ... [case ids]` resolves the set, checks its frozen files (heldout_v3: the DEC-038 gate, ACTIVE items only, none PENDING, configurations `legacy s3t`) and the passwords of the eval accounts its questions need. It calls no API and no model, and prints the set, the number of questions, their ids and the ids not asked. `ci_batch.sh` runs it first; `ci_batch.sh --validate-only` stops after it. |
| `heldout_v3_diag.py` | Diagnosis of a held-out v3.1 run with no text printed. `table <decrypted dir>` (the owner, on the decrypted `private-results.tar.gz.age`): one row per configuration, run and item: HTTP status, latency, answer route, answer status, chunks retrieved, citation count, cited and gold codes, "cites a gold document", "every gold value found", fail reason codes; then the reason counts. `access`: per item asked, its role and whether that account may see each gold document (corpus V2 manifest) and whether it is DRAFT. Every field printed is checked against a name/code pattern. |
| `heldout_status.py` | DEC-039 run status, at the top of the public `summary.md` of a held-out workflow, also when the job failed. It gives the status, the failing step and its exit code (an exit trap sourced through `BASH_ENV`), and the questions sent to the API, counted from the uvicorn access log (`unknown` when there is no access line). Standard library only. |
| `heldout_publish.sh` | DEC-039: splits a held-out run. The public folder gets only the lock, `summary.md` and `verdict.json`. The rest is age-encrypted for `HELDOUT_AGE_RECIPIENT` on a GitHub-hosted runner (the step fails without the key), or copied to `HELDOUT_PRIVATE_DIR/<run id>` on a self-hosted one. `question_leak.py scan <folder>` then checks the public folder before the upload. |
| `question_leak.py` | Hashed word 4-grams of dev and held-out questions in `question_fingerprints.json`, no question text. `check` compares added `app/` lines, `overlap` compares the two sets; both exit 2 when the source is missing, empty or stale. |

The questions, reference grade and manifests live under the git-ignored `artifacts/` directory.
